# 구양이 디자인 시스템

> **상태: 구현 전 기준.** 방향과 규칙은 확정이고, 토큰 값과 컴포넌트 치수는 화면을 만들기 전에 정한 기준값이다.
> Sprint 3 (도감 화면)에서 실제로 구현한 값으로 이 문서를 갱신하고, 그때 `.impeccable/design.json` 도 함께 만든다.
> 제품 맥락은 [../PRODUCT.md](../PRODUCT.md), 요구사항 원본은 [specs/PRD.md](specs/PRD.md).

## Overview

**밤의 책상 위에 펼친 콜렉트북.** 사용자는 밤에 방에서 굿즈를 정리하면서 휴대폰으로 이 앱을 연다. 그래서 어두운 화면이 기본이고, 화면의 주인공은 포켓 속지처럼 늘어선 도감 칸이다.

세 가지가 이 시스템을 이룬다.

| 요소 | 출처 | 쓰는 곳 |
|---|---|---|
| **포켓** | 콜렉트북 바인더의 포켓 속지 | 도감 칸, 세트 구분. 시스템의 기본 |
| **소인** | 우편 소인 (날짜가 든 둥근 도장) | 교환이 끝난 아이템, 컴플리트한 세트. 그 밖에는 쓰지 않는다 |
| **교환 그림** | 사람과 화살표로 그린 순환 | 1:1 과 3자 순환 매칭, 교환 진행 |

이렇게 보이면 실패다: 유아·키즈 앱, 중고거래 앱, 흔한 AI 생성 앱, 게임 가챠 화면. 아래 규칙마다 어느 것을 막기 위한 것인지 적어 둔다.

### 다섯 가지 규율

1. **색 있는 버튼은 누를 수 있는 것에만.** 눌러도 아무 일이 없는 곳에 버튼 색을 쓰지 않는다.
2. **기한 순으로, 볼 때까지.** 기한이 걸린 것은 기한이 가까운 순으로 정렬한다. 상태가 바뀐 항목은 사용자가 볼 때까지 표시를 유지한다.
3. **미보유 칸에는 색이 없다.** 색은 가진 것에만 있다. 미보유는 무채색 실루엣이다.
4. **도감 그리드가 화면의 뼈대다.** 줄바꿈은 칸 단위로만 한다. 칸 크기를 어중간하게 줄이지 않는다.
5. **칸 아래 이름표 한 줄.** 사진이 없어도 칸이 무엇인지 알 수 있어야 한다.

## Colors

MVP 는 어두운 화면만 만든다. 토큰 이름은 **역할**로 짓는다 (`pink` 가 아니라 `give`). 나중에 밝은 화면을 추가할 때 이름은 그대로 두고 값만 한 벌 더 정한다. 컴포넌트에서 색상 값을 직접 쓰지 않는다.

| `surface` | `#221E28` | 미정 | 카드, 포켓 칸, 시트 |

### 색 규칙

- **색만으로 구분하지 않는다.** 구/양과 모든 상태는 글자나 모양을 항상 함께 표시한다 (색각 이상 대응). 구와 양은 색 말고도 두 가지가 다르다: 글자("구"/"양")와 배지 모양(테두리만 / 면 채움).
- **`want` 와 `give` 는 구/양 표시에만 쓴다.** 배지, 수량 숫자, 교환 그림에서 내 leg 의 표식까지다. 배경, 카드, 버튼, 머리말, 장식에 쓰지 않고 면적을 넓히지 않는다 (키즈 앱 인상 방지).
- **`complete` 는 소인과 컴플리트 표시에만 쓴다.** 기한 임박(`status-urgent`)과 색이 가까우므로, 둘은 모양(소인 / 시계 아이콘이 붙은 칩)으로 구분한다.
- **미보유 칸은 무채색이다.** `silhouette` 와 `text-muted` 만 쓴다.
- 주요 버튼은 밝은 면(`action`)에 어두운 글자다. 화면에서 가장 밝은 면이 "지금 할 일"이다.
- 순수한 검정(`#000`)과 순수한 흰색(`#FFF`)은 쓰지 않는다.

## Typography

- **글꼴**: LINE Seed Sans KR (Regular 400, Bold 700). 못 불러오면 시스템 글꼴. 라이선스와 서브셋 용량은 Sprint 3 에서 확인하고, 문제가 있으면 이 문서를 고친다.
- **숫자**: 수량, 기한, 송장번호는 고정폭 숫자(`font-variant-numeric: tabular-nums`)로 쓴다. 숫자가 바뀌어도 자리가 흔들리지 않는다.
- 굵기는 두 가지만 쓴다. 강조는 굵기로 하고 색으로 하지 않는다.

| 이름 | 크기 | 굵기 | 줄 간격 | 쓰는 곳 |
|---|---|---|---|---|
| `title` | 24px | 700 | 1.3 | 화면 제목 |
| `heading` | 20px | 700 | 1.35 | 세트 이름, 카드 제목 |
| `body` | 16px | 400 | 1.55 | 본문, 입력란 |
| `label` | 14px | 700 | 1.4 | 버튼, 배지, 탭 |
| `nameplate` | 12px | 400 | 1.35 | 칸 아래 이름표, 보조 정보 |

- 12px 보다 작은 글자는 쓰지 않는다. 입력란은 16px 이상이다 (iOS 가 화면을 확대하지 않게).
- 본문 한 줄은 한글 기준 35자 안팎을 넘기지 않는다.
- 크기는 `rem` 으로 쓴다. 사용자가 글자를 키우면 따라 커진다.

## Layout

- **모바일 우선.** 기준 폭 360~430px. 가로 여백 16px.
- 간격은 4px 단위: 4 / 8 / 12 / 16 / 24 / 32.
- 누를 수 있는 것은 **44×44px 이상**이다.
- 화면 아래에 탭 바를 둔다: 도감 / 매칭 / 알림 / 내 정보. 엄지가 닿는 곳에 주요 버튼을 둔다.
- 홈 화면에 추가한 PWA 에서 노치와 홈 표시줄을 피한다 (`env(safe-area-inset-*)`).

### 도감 그리드

| 화면 폭 | 열 수 |
|---|---|
| 480px 미만 | 3 (4열과 실제 화면으로 비교해 Sprint 3 에서 결정) |
| 480px 이상 | 4 |
| 768px 이상 | 6 |

- 칸 사이 간격 8px.
- **칸 비율은 세트마다 다르다** (`sets.cell_ratio`). 굿즈마다 모양이 다르기 때문이다. 한 세트 안에서는 모든 칸이 같은 비율이다.

  | 값 | 칸 모양 | 맞는 굿즈 |
  |---|---|---|
  | `1:1` (기본) | 정사각형 | 캔뱃지, 코스터처럼 원형·정사각형인 것 |
  | `3:4` | 세로로 긴 직사각형 | 카드, 브로마이드처럼 카드형인 것 |

- 사진은 잘리지 않게 칸 안에 맞춘다. 원형 굿즈도 칸은 네모다 (포켓은 네모다). 칸을 원으로 자르지 않는다.
- 열 수는 위 표의 값으로만 바뀐다. 그 사이 폭에서는 칸이 고르게 늘어난다.
- 세트 하나는 머리(세트 이름, `12 / 26` 같은 진행 숫자, 컴플리트면 소인) + 그리드다.

## Elevation & Depth

- 깊이는 **면의 밝기**로 나타낸다: `bg` → `surface` → `surface-raised`. 그림자는 쓰지 않는다.
- 아래에서 올라오는 시트와 대화 상자만 뒤에 어두운 막(`bg` 60%)을 깐다.
- 흐림 효과(유리 느낌), 빛 번짐, 색 그라데이션 배경은 쓰지 않는다 (AI 생성 앱 인상 방지).

### 슬리브 광택

포켓 칸의 유일한 질감이다. 절제한다 (가챠 화면 인상 방지).

- **보유한 칸에만** 둔다. 미보유 칸에는 없다.
- 칸 위쪽 가장자리의 밝은 선 1px (흰색 12%) + 위에서 아래로 사라지는 아주 옅은 겹침 (흰색 6% → 0%). 이것이 전부다.
- **움직이지 않는다.** 반짝임, 빛이 지나가는 효과, 기울기에 반응하는 효과, 무지개빛(홀로그램)을 쓰지 않는다. 컴플리트한 세트도 마찬가지다.

## Shapes

- 모서리: 포켓 칸 6px, 버튼·입력란 10px, 카드·시트 14px, 배지 완전히 둥글게.
- 모든 것을 크게 둥글리지 않는다. 포켓 칸은 실제 속지처럼 거의 각지다 (키즈 앱 인상 방지).
- 아이콘은 선 굵기 1.5px 의 선 아이콘 한 벌(lucide, shadcn/ui 기본)만 쓴다. 이모지는 문구의 🐾 하나뿐이다.
- 둥근 도장 모양은 소인에만 쓴다.

## Components

모두 **구현 전 기준**이다. shadcn/ui 컴포넌트를 바탕으로 하고, 아래는 구양이에만 있는 것과 고쳐 쓸 것이다.

### Buttons

- **주요**: `action` 면 + `on-fill` 글자, 높이 48px. 한 화면에 하나.
- **보조**: `surface-raised` 면 + `text` 글자.
- **위험** (거절, 교환 취소, 신고): `status-dispute` 테두리와 글자. 면을 채우지 않는다. 누르면 확인을 한 번 받는다.
- 초점 표시: `text` 색 2px 선, 2px 띄움. 지우지 않는다.
- 비활성: 불투명도 40%. 왜 누를 수 없는지 버튼 가까이에 글로 적는다.

### 구/양 배지

| | 구 | 양 |
|---|---|---|
| 글자 | "구" | "양" |
| 모양 | 테두리만 (1.5px), 안은 `bg` | 면을 채움 |
| 색 | `want` 테두리와 글자 | `give` 면 + `on-fill` 글자 |
| 수량 | 수량이 2 이상이면 "양 2" 처럼 붙인다 | |

- 높이 20px, 글자 `label` 12px 굵게. 칸의 오른쪽 위에 둔다.
- 흑백으로 봐도 테두리와 채움, 글자로 구분된다.
- 보조 기술용 이름: "구, 구하는 아이템", "양 2개, 내놓을 수 있는 아이템".

### 포켓 칸

도감의 한 칸 = 아이템 하나. 칸 + 아래 이름표 한 줄.

| 상태 | 칸 안 | 이름표 | 배지 |
|---|---|---|---|
| 미보유 | `silhouette` 색 실루엣, `border-strong` 테두리, 광택 없음, 색 없음 | `text-muted` | 구 |
| 보유 | 실물 사진 (없으면 아이템 이름을 칸 안에 크게), 슬리브 광택 | `text` | 수량 `×2`, 양이 있으면 양 |
| 예약 중 | 보유와 같음 + "교환 중" 칩 (`status-info`) | `text` | |
| 교환으로 받음 | 보유와 같음 + 소인 | `text` | |
| 교환 꺼 둠 | 보유와 같음, 양 배지 없음 + "소장만" 글자 | `text` | |

- 이름표는 한 줄이고 넘치면 말줄임한다. 전체 이름은 칸을 누르면 나온다.
- 칸을 누르면 아래에서 시트가 올라와 보유 수량·소장 개수·교환 여부를 고친다. 수량은 − / 숫자 / + 로 바꾼다. 소장 개수를 건드리지 않은 칸은 "하나 소장"(기본)이다.
- 세트마다 "교환 시작" 스위치가 있다 (기본 꺼짐, 한 번 눌러 켠다). 꺼진 세트의 칸에는 구/양 배지가 없다. 켤 때 구의 범위를 고르게 한다: "빈칸 전부 구하기"(기본 선택) / "고른 것만 구하기". 화면 배치와 문구는 Sprint 3 (TASKS 3.4) 에서 정한다.
- 사진이 하나도 없는 세트도 실루엣 + 이름표 + 배지로 완전히 쓸 수 있어야 한다.

### 소인

날짜가 든 둥근 도장. **두 곳에만** 쓴다.

| 쓰는 곳 | 가운데 글자 | 크기 |
|---|---|---|
| 교환으로 받은 아이템의 칸 | 교환 완료 날짜 `2026.11.15` | 칸 폭의 45%, 오른쪽 아래에 겹침 |
| 컴플리트한 세트의 머리 | 컴플리트 날짜 + "컴플리트" | 64px |

- 모양: 이중 원 테두리, 위쪽 둘레에 "구양이", 가운데 날짜. 면을 채우지 않는 선 그림이다. 색은 `complete`.
- 기울기: −8도 고정. 무작위로 돌리지 않는다.
- 찍힐 때: 한 번, 200ms 동안 살짝 커졌다가 제자리로 온다. 반복하지 않고, 빛나거나 터지는 효과가 없다.
- 보조 기술용 이름: "2026년 11월 15일 교환 완료".
- 배지, 버튼, 장식, 빈 상태에 소인 모양을 쓰지 않는다. 흔해지면 뜻이 없어진다.
- 컴플리트한 세트의 **공유 카드**에도 컴플리트 소인을 찍는다 (아래 "공유 카드").

### 공유 카드

사용자가 버튼을 눌러 만드는 세트 하나의 이미지 (PRD "도감 공유 이미지", Sprint 3). 앱 밖(X 등)에서 보이는 구양이의 유일한 얼굴이다. 앱과 같은 어두운 화면 토큰을 쓴다.

**굿즈 사진을 넣지 않는다** (저작권). 사진이 등록된 세트도 이름표만으로 만든다. 그래서 칸은 색이 아니라 **채움과 테두리**로 보유를 구분한다.

- 크기: 1080×1350px (4:5 세로). 바깥 여백 64px.
- 위에서 아래로:

| 영역 | 내용 |
|---|---|
| 머리 | 세트 이름(`title` 을 이미지 크기에 맞게 키움) + 컴플리트율 `18 / 26 · 69%` (고정폭 숫자) |
| 포켓 그리드 | 세트의 모든 아이템. 칸 비율은 세트의 `cell_ratio` 를 따른다 |
| 구 목록 | 구 배지 + 아이템 이름을 구 우선순위 순으로. 자리가 모자라면 "외 n개". 컴플리트한 세트는 이 영역이 없다 |
| 양 목록 (선택) | 켰을 때만. 양 배지 + 아이템 이름. **종류만 적고 수량은 적지 않는다.** 자리가 모자라면 "외 n개" |
| 바닥 | 왼쪽: 구양이 자리 + 서비스 주소. 오른쪽: 만든 날짜 `2026.11.15 기준`, 켰을 때만 닉네임 |

- 그리드 열 수: 아이템이 12개 이하면 4열, 30개 이하면 6열, 그보다 많으면 8열.
- 칸:

| | 칸 | 칸 안 | 표식 |
|---|---|---|---|
| 보유 | `surface-raised` 로 채움, 테두리 없음 | 아이템 이름, `text` 굵게 | 없음 |
| 미보유 | 채우지 않음, `border-strong` 점선 테두리 | 아이템 이름, `text-muted` | 구 배지 |

  이름은 칸 안에서 두 줄까지 쓰고 넘치면 말줄임한다. 슬리브 광택은 넣지 않는다.
- 컴플리트한 세트: 그리드 오른쪽 아래에 컴플리트 소인(160px)을 겹쳐 찍는다.
- 넣지 않는 것: 굿즈 사진, 공식 로고, 보유 수량, 소장 개수, 양의 수량, 평판, 매칭·교환 내역.
- 닉네임: 기본은 넣지 않는다. 미리보기 화면의 "닉네임 넣기" 스위치(기본 꺼짐)를 켰을 때만 바닥 오른쪽에 넣는다.
- 양 목록: 기본은 넣지 않는다. "양 목록 넣기" 스위치(기본 꺼짐)를 켰을 때만 구 목록 아래에 넣는다. 그리드의 칸에는 양 표시를 하지 않는다.
- 만든 날짜는 항상 넣는다 (공유된 이미지는 시간이 지나면 실제 도감과 달라진다).
- 미리보기 화면: 이미지 미리보기 → 닉네임 스위치, 양 목록 스위치 → "이미지 저장"(주요 버튼), "공유"(보조 버튼). 스위치를 바꾸면 미리보기가 바로 바뀐다.
- 이미지에 들어가는 글자는 12px 규칙 대신, 1080px 폭에서 가장 작은 글자가 24px 이상이 되게 한다 (휴대폰에서 줄여 봐도 읽히게).

### 교환 그림

"누가 누구에게 무엇을 보내는가"를 보여 주는 그림. 1:1 과 3자 순환이 **같은 그림 언어**를 쓴다. 매칭 제안 화면과 교환 진행 화면에 나온다.

구성 요소:
- **사람** = 원. 안에 닉네임 첫 글자, 아래에 닉네임. **나**는 `text` 색 굵은 테두리 + "나" 글자, 다른 사람은 `border-strong` 테두리.
- **화살표** = leg 하나 (아이템 하나가 한 사람에게서 다른 사람에게로).
- **아이템 표** = 화살표 가운데에 얹는 작은 칸 (사진 또는 이름) + 이름표.
- 내가 보내는 화살표에는 양 배지, 내가 받는 화살표에는 구 배지를 붙인다. 내가 끼지 않은 화살표(3자 순환의 나머지 하나)에는 배지가 없다.

배치:

```
1:1                         3자 순환

  (나) ──── 양 ────▶ (달)          (달)
  (나) ◀─── 구 ───── (달)         ▲    ╲
                                 ╱      ▼
                              (나) ◀── (별)
```

- 1:1: 두 사람을 가로로 두고 화살표 두 개를 위아래로 나란히 그린다. 위가 내가 보내는 것.
- 3자 순환: 세 사람을 삼각형으로 두고 **나는 항상 왼쪽 아래**, 화살표는 시계 방향이다. 지하철 노선도나 지도 같은 세계관 장식은 없다. 원, 화살표, 아이템 표뿐이다.

leg 별 진행 상태 (화살표의 선 모양 + 색 + 아이콘 + 글자, 네 가지가 함께 바뀐다):

| 상태 | 선 | 색 | 아이콘과 글자 |
|---|---|---|---|
| 아직 (제안 중, 발송 전) | 점선 | `text-muted` | "발송 전" |
| 배송 중 | 실선 | `status-info` | 상자 아이콘 "배송 중" |
| 수령 | 굵은 실선 | `status-done` | 체크 아이콘 "수령" |
| 기한 임박 | 점선 | `status-urgent` | 시계 아이콘 + 남은 시간 |
| 기한 넘김 | 점선 | `status-dispute` | 경고 아이콘 "기한 넘김" |

- 그림 아래에 **같은 내용을 글 목록으로** 항상 둔다: "나 → 달빛: 미쿠 코스터 · 배송 중". 그림은 장식으로 처리하고(`aria-hidden`), 화면 낭독기는 목록을 읽는다. 그림을 못 봐도 잃는 정보가 없어야 한다.
- 제안 화면에서는 사람 아래에 평판 한 줄을 둔다: "완료 5 · 미발송 0 · 무응답 1".
- 화살표가 움직이는 효과(흐르는 점선 등)는 쓰지 않는다.

### Cards / Containers

- 카드: `surface` 면, 모서리 14px, 안쪽 여백 16px, 테두리와 그림자 없음.
- 카드 안에 카드를 넣지 않는다.
- **매칭 제안 카드**: 머리말(구양이 자리 + "구양이가 물어왔어요 🐾") → 교환 그림 → 기한 칩 → 수락 / 거절.
- **기한 칩**: 시계 아이콘 + "오늘 21:00 까지" 처럼 끝나는 시각을 적는다. 6시간 넘게 남으면 `text-muted`, 6시간 이하면 `status-urgent`, 넘기면 `status-dispute`. 6시간은 기준값이고 Sprint 5 에서 정한다.
- **배송 정보 카드**: 내가 보낼 상대의 것만. 이름·전화번호·주소를 줄마다 두고 줄마다 복사 버튼. 화면 갈무리 주의 문구를 아래에 둔다.

### Inputs / Fields

- `surface-raised` 면, `border-strong` 테두리 1px, 높이 48px, 글자 16px.
- 라벨은 입력란 위에 항상 보이게 둔다. 안내 글자(placeholder)를 라벨 대신 쓰지 않는다.
- 오류: 테두리 `status-dispute` + 입력란 아래에 경고 아이콘과 글. 무엇이 틀렸고 어떻게 고치는지 적는다.

### Navigation

- 아래 탭 바: 아이콘 + 글자 라벨. 선택된 탭은 `text` 색과 굵은 글자, 나머지는 `text-muted`.
- 알림과 매칭 탭의 새 소식은 `status-urgent` 점 + 개수 숫자. 사용자가 볼 때까지 유지한다 (규율 2).
- 매칭 목록의 정렬: 기한이 걸린 것이 위, 기한이 가까운 순.

### 구양이 자리

캐릭터 그림은 아직 없다. **그림 없이도 모든 화면이 성립해야 하고**, 그림이 준비되면 아래 자리에만 넣는다. 그때까지는 자리를 비워 두지 않고 접는다 (빈 상자나 임시 그림을 두지 않는다).

| 자리 | 크기 | 그림이 오기 전 |
|---|---|---|
| 매칭 제안 카드의 머리말 왼쪽 | 40px | 문구의 🐾 만 |
| 빈 상태 (도감 비어 있음, 매칭 없음, 알림 없음) | 120px | 문구만 |
| 교환 완료 화면 | 160px | 소인 + 문구 |
| 온보딩 첫 화면 | 160px | 문구만 |
| 세트 머리의 스티커 자리 (바인더 표지에 붙인 스티커처럼) | 32px | 없음 |
| 소인 가운데 위 | 소인의 20% | "구양이" 글자만 |
| 오류·404 화면 | 120px | 문구만 |
| 공유 카드 바닥 왼쪽 | 96px (1080px 이미지 기준) | 글자 "구양이" 만 |
| 앱 아이콘, 푸시 알림 아이콘 | | 글자 "구양" 으로 만든 임시 아이콘 |

- 구양이는 도감 칸, 버튼, 탭 바, 교환 그림 안에는 나오지 않는다. 일하는 화면을 가리지 않는다.
- 그림이 준비되면: 어두운 바탕에서 보이는 선과 색, 투명 배경, 위 크기에서 알아볼 수 있는 단순함.

## Motion

- 상태가 바뀐 것을 알리는 데만 쓴다. 길이 150~200ms, 감속(ease-out).
- 쓰는 것: 시트가 올라옴, 칸이 실루엣에서 컬러로 바뀜(서서히 나타남), 소인이 한 번 찍힘, 눌림 반응.
- 쓰지 않는 것: 튀어 오름, 반짝임, 색종이, 빛줄기, 흔들림, 뒤집히는 카드, 숫자가 올라가는 연출, 반복되는 움직임 (가챠 화면 인상 방지).
- `prefers-reduced-motion` 이면 움직임을 없애고 바로 바뀐다.

## 고양이 톤 문구 가이드

구양이는 **남는 굿즈를 물어다 주는 고양이**다. 문구는 구양이가 옆에서 일해 주는 느낌을 주되, 정보를 가리지 않는다.

### 원칙

1. **해요체로 쓴다.** "했어요", "해 주세요". 반말, 합쇼체("하십시오"), "~냥" 말투를 쓰지 않는다 (키즈 앱 인상 방지).
2. **구양이는 3인칭이다.** "구양이가 물어왔어요". 구양이가 "나는", "제가" 라고 말하지 않는다.
3. **고양이다움은 동사에 담는다.** 물어오다, 찾아오다, 둘러보다, 지키다, 기다리다, 적어 두다. 의성어("야옹", "골골")는 쓰지 않는다.
4. **🐾 는 한 화면에 한 번까지.** 좋은 소식(제안 도착, 교환 완료, 컴플리트)에만 붙인다. 버튼, 오류, 기한 경고에는 붙이지 않는다. 다른 이모지는 쓰지 않는다.
5. **무거운 일일수록 담백하게.** 기한, 분쟁, 신고, 오류, 개인정보에서는 고양이 표현을 빼고 **무슨 일인지 → 언제까지인지 → 무엇을 하면 되는지** 순서로 쓴다.
6. **기한은 끝나는 시각으로 적는다.** "24시간 안에" 가 아니라 "내일 21:00 까지". 시간 값은 `app_settings` 에서 온 것으로 계산한다. 문구에 숫자를 박아 넣지 않는다.
7. **사용자를 탓하지 않는다.** "잘못 입력했어요" 가 아니라 무엇을 넣으면 되는지 쓴다.
8. **버튼은 하는 일을 그대로 쓴다.** "수락하기", "보냈어요", "받았어요". "확인", "네" 만 있는 버튼을 만들지 않는다.
9. **푸시와 이메일에는 이름·주소·전화번호를 넣지 않는다.** 무슨 일인지, 기한, 바로가기만 담는다.

### 낱말

| 쓴다 | 쓰지 않는다 | 이유 |
|---|---|---|
| 교환 | 거래, 판매, 구매, 나눔 | 교환만 하는 서비스다 (중고거래 앱 인상 방지) |
| 구 / 양 | 삽니다 / 팝니다, 구해요 / 드려요 | 팬들이 쓰는 말 그대로 |
| 내놓다, 보내다, 받다 | 팔다, 사다, 가격, 시세, 무료 | 돈과 관련된 말을 쓰지 않는다 |
| 채우다, 모으다, 정리하다 | 뽑다, 당첨, 대박, 득템, 레어, 운 | 뽑기의 흥분이 아니라 정리의 만족 (가챠 화면 인상 방지) |
| 세트, 아이템, 도감, 소장 | 상품, 물건, 매물, 재고 | |
| 매칭, 1:1, 3자 순환 | 딜, 트레이드 | |
| 발송, 수령, 송장번호 | 배송 완료 처리, 인수 | |

## Do's and Don'ts

### Do:

- 미보유는 무채색 실루엣 + 이름표, 보유는 컬러 + 절제한 슬리브 광택으로 구분한다.
- 구/양과 모든 상태에 글자나 모양을 함께 쓴다.
- 소인은 교환 완료와 컴플리트에만 찍는다.
- 1:1 과 3자 순환을 같은 교환 그림으로 그리고, 아래에 같은 내용의 글 목록을 둔다.
- 기한은 끝나는 시각으로 적고, 기한 순으로 정렬한다.
- 색은 역할 토큰으로만 쓴다.
- 사진과 캐릭터 그림이 없어도 화면이 완성되게 만든다.

### Don't:

- **유아·키즈 앱**: 분홍·민트를 배경이나 넓은 면에 쓰지 않는다. 모든 모서리를 크게 둥글리지 않는다. "~냥" 말투, 통통 튀는 움직임을 쓰지 않는다.
- **중고거래 앱**: 가격, 판매, 거래라는 말과 가격표 모양을 쓰지 않는다. 주황색을 주된 색으로 쓰지 않는다. 사용자 사진 목록(피드) 구조를 만들지 않는다.
- **흔한 AI 생성 앱**: 보라·파랑 그라데이션, 유리 느낌 흐림, 빛 번짐, 카드 안의 카드, 한쪽에만 굵은 색 띠가 있는 카드, 뜻 없는 아이콘 타일을 쓰지 않는다.
- **게임 가챠 화면**: 반짝임, 무지개빛 광택, 등급 색(레어·에픽), 별 개수, 색종이, 빛줄기, 뒤집히는 카드, 뽑기 말투를 쓰지 않는다.
- 색만으로 뜻을 전하지 않는다.
- 구양이 그림이 올 자리에 임시 그림이나 빈 상자를 두지 않는다.
- 공유 카드에 굿즈 사진, 공식 로고를 넣지 않는다.

## Sprint 3 확인 항목

이 문서는 구현 전 기준이다. Sprint 3 에서 아래를 실제 화면으로 확인하고, 결과로 이 문서의 값을 고친다.

- [ ] **모바일 그리드 3열과 4열**을 실제 화면(360px, 390px, 430px)으로 비교해 정한다. 이름표가 읽히는지, 칸을 누르기 쉬운지, `1:1` 과 `3:4` 세트 모두에서 본다.
- [ ] **색각 이상 시뮬레이션**(적색맹, 녹색맹, 청색맹, 전색맹)으로 구 / 양 / 완료 / 기한 임박 / 컴플리트가 구분되는지 확인한다. 색이 겹쳐 보여도 글자와 모양으로 구분되어야 통과다. 특히 `status-urgent` 와 `complete`, `status-done` 과 `want`.
- [ ] **LINE Seed Sans KR** 의 라이선스(웹 임베딩, 이미지 생성에 쓰는 것 포함)와 웹폰트 용량(서브셋 후)을 확인한다. 문제가 있으면 글꼴을 바꾸고 이 문서를 고친다.
- [ ] 대비 계산 표를 실제 구현 값으로 다시 계산한다.
- [ ] 토큰과 컴포넌트 치수를 실제 값으로 갱신하고 `.impeccable/design.json` 을 만든다. "구현 전 기준" 표시를 뗀다.

확정이라 다시 묻지 않는 것: "~냥" 말투 금지, 기한 칩이 주황으로 바뀌는 기준 6시간, 대비 기준 미달 두 개(미보유 실루엣, 장식용 구분선)를 그대로 두는 것.
