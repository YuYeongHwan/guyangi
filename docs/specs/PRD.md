# 구양이 PRD

랜덤 굿즈를 위한 "내 굿즈 도감" + "1:1 / 3자 순환 교환 자동 매칭" 웹 서비스.
이 문서는 **무엇을, 왜** 만드는지만 다룬다. 구조·스키마·작업 분해는 docs/adr, docs/diagrams, TASKS.md 에서 다룬다.

## 1. 문제

랜덤 굿즈(콜라보 카페 특전, 페어 특전, 쿠지, 랜덤 캔뱃지)는 원하는 종류를 골라 살 수 없어서, 팬들은 남는 것(양)을 주고 없는 것(구)을 받는 교환으로 세트를 채운다. 지금은 이 교환을 X에서 한다.

- 교환글을 직접 올리고, 검색하고, 상대의 구/양 목록과 내 목록을 눈으로 맞춰 봐야 한다.
- 서로 원하는 것이 정확히 맞는 1:1 상대를 찾기 어려워서, 조건이 맞는 사람이 있어도 성사되지 않는다.
- A→B→C→A 로 도는 3자 순환 교환은 세 사람의 목록을 동시에 봐야 해서 사람이 찾을 수 없다.
- 내가 무엇을 몇 개 가지고 있는지 따로 정리해 둔 곳이 없어서 교환글을 쓸 때마다 다시 센다.

그 결과 남는 굿즈는 쌓이고, 세트는 완성되지 않는다.

## 2. 근거

- 운영자 본인의 교환 경험: 교환글 작성, 검색, 목록 대조에 드는 시간과 성사 실패.
- X 관찰: 같은 세트의 구/양 교환글이 꾸준히 올라오고, 같은 글이 반복해서 재게시된다.
- **가정 — 검증 필요**: "성사가 어렵다"의 크기(교환글 대비 성사 비율)는 측정한 적이 없다. → 검증 방법은 9장 참고.
- **가정 — 검증 필요**: 3자 순환이 실제로 성립할 만큼 구/양이 엇갈리는지. → 초기 도감 데이터로 확인.

## 3. 사용자

### 페르소나 A — "채우는 사람" 민서
- 한 장르를 깊게 파는 팬. 콜라보 카페에 여러 번 가서 특전이 20장 넘게 쌓였고, 최애 캐릭터는 아직 못 뽑았다.
- X에 교환글을 올려 봤지만 답이 없거나, 상대가 원하는 것이 나에게 없었다.
- 원하는 것: 최애와 세트 컴플리트. 남는 것은 누구에게든 주고 싶다.
- 서비스를 쓰는 순간: 카페에 다녀온 직후, 새로 뽑은 것을 정리할 때.

### 페르소나 B — "모으는 사람" 지우
- 교환보다 수집 자체를 즐긴다. 여러 세트를 조금씩 가지고 있고, 무엇을 가졌는지 한눈에 보고 싶어 한다.
- 모르는 사람과 연락하고 주소를 주고받는 일이 부담스러워서 교환은 거의 해 본 적이 없다.
- 원하는 것: 내 수집 현황을 예쁘게 정리하고 채워 가는 재미. 교환은 부담이 없을 때만.
- 서비스를 쓰는 순간: 굿즈를 새로 샀을 때, 정리하고 싶을 때.

### 대상이 아닌 사람
- 굿즈를 팔거나 사려는 사람 (판매·구매 기능 없음)
- 대량 되팔이, 대리 구매자

## 4. 가설

우리는 **도감에 보유 현황만 입력하면 1:1과 3자 순환 교환 상대를 자동으로 찾아 주는 기능**이
**한 장르를 모으는 랜덤 굿즈 팬**의 **교환 상대 찾기 실패**를 해결한다고 믿는다.
**전원이 수락한 매칭의 50% 이상이 교환 완료까지 가고, 3개월 안에 3자 순환이 30건 완료되면** 맞았다고 본다.

두 기능의 역할:
- **도감** — 혼자 써도 재미있는 기능. 교환 상대가 없어도 가입할 이유가 되고, 매칭에 필요한 데이터를 만든다.
- **자동 매칭** — 함께 쓸수록 가치가 커지는 기능. 도감 사용자가 늘수록 성사율이 올라간다.

## 5. 목표와 비목표

### 목표
1. 도감 입력만으로 교환 가능한 상대를 사용자가 찾지 않아도 알려 준다.
2. 사람이 찾을 수 없는 3자 순환 교환을 성사시킨다.
3. 교환 상대가 없어도 도감만으로 쓸 가치가 있다.
4. 모르는 사람과의 교환에서 미발송 걱정을 줄인다.

### 비목표
- **판매·구매·결제** — 돈이 오가는 기능은 만들지 않는다. 교환만 한다.
- **중개 수수료** — 받지 않는다.
- **차액 정산** — 가치가 다른 굿즈 사이의 돈 보전은 지원하지 않는다.
- **4자 이상 순환** — 참여자가 늘수록 이탈 위험이 커진다. 3자까지만.
- **배송 대행·안전결제·보증금** — 운영자가 물건이나 돈을 맡지 않는다.

## 7. MVP 범위

### 포함
| 기능 | 내용 |
|---|---|
| 로그인 | 카카오, 구글. 만 14세 이상 확인 |
| 세트 카탈로그 | 운영자가 세트와 아이템을 등록. 초기 시드는 프로세카 세트 3개. 구조는 장르에 독립적 |
| 세트 추가 요청 | 사용자가 없는 세트를 요청. 등록은 운영자가 한다 |
| 도감 | 세트 추가, 아이템별 보유 수량 입력, 컴플리트 표시. 세트별 교환 시작 스위치(기본 꺼짐)를 켠 세트만 구/양 자동 계산. 기본은 종류마다 하나 소장, 칸별로 소장 개수·내놓지 않음 지정 |
| 도감 공유 이미지 | 사용자가 버튼을 눌러 세트 하나를 이미지로 만든다. 굿즈 사진 없이 이름표로 구성. 닉네임과 양 목록(종류만) 표시는 선택이고 기본은 표시하지 않음 |
| 구 범위와 우선순위 | 세트마다 "빈칸 전부 구하기" 또는 "고른 것만 구하기". 원하는 아이템에 우선순위 지정 |
| 1:1 매칭 | 자동 제안, 수락·거절, 만료 |
| 3자 순환 매칭 | 자동 제안, 전원 수락 시 성사. 교환 완료 3회 이상이고 미발송 신고 0회인 사용자만 |
| 교환 진행 | 배송 정보 교환, 발송·수령 표시, 기한 초과 처리, 완료 시 도감 자동 반영 |
| 최소 평판 | 교환 완료 횟수 + 미발송 신고 횟수 + 무응답 횟수를 프로필에 표시. 3자 순환 참여 조건에 사용 |
| 알림 | 인앱 + 웹 푸시 + 이메일. 기한이 걸린 알림(수락 요청, 발송 기한 경고, 분쟁 전환)은 푸시와 이메일 모두, 그 외는 인앱과 푸시 |
| 신고 | 미발송 신고, 운영자 확인 후 이용 제한 |
| 운영자 화면 | 세트 등록, 요청·신고 처리 |

| 기능 | 미루는 이유 |

| 사용자 간 채팅 | 운영·신고 부담. 교환 진행 화면의 상태 표시로 대신한다 |

| 묶음 교환(2:2) | 매칭 한 건은 참여자마다 아이템 하나씩. 같은 두 사람 사이에 여러 아이템이 오가는 확장은 막지 않게 설계만 해 둔다 |
| 도감 공개 프로필 | 다른 사용자가 내 도감을 열어 보는 기능. 도감 단독 공개 이후 반응을 보고 정한다. (사용자가 직접 만드는 공유 이미지는 MVP 에 포함) |
| 여러 장르 확장 | 한 장르에서 매칭 밀도를 먼저 확인한다 |
| 네이티브 앱 | 모바일 웹(PWA)으로 시작한다 |

## 8. 기능별 수용 기준

### 도감
- 세트를 추가하면 그 세트의 모든 아이템이 미보유(실루엣) 상태로 보인다.
- 보유 수량을 1 이상으로 바꾸면 그 칸이 컬러로 바뀐다.
- 세트를 추가하고 수량을 적는 것만으로는 교환 대상이 되지 않는다. 세트의 "교환 시작" 을 켜기 전에는 그 세트의 아이템이 양에도 구에도 잡히지 않고, 매칭 제안도 오지 않는다. 스위치의 기본은 꺼짐이고 한 번 눌러 켠다.
- 교환을 켜면 기본은 "종류마다 하나는 소장" 이다. 하나뿐인 굿즈는 양으로 나가지 않는다.
- 교환을 켤 때 구의 범위를 고른다: "빈칸 전부 구하기"(기본 선택) 또는 "고른 것만 구하기". 고른 것만 구하기에서는 고르지 않은 빈칸이 구에 잡히지 않는다.
- 칸마다 예외를 둘 수 있다: 이 칸은 내놓지 않음, 이 칸의 소장 개수 변경.
- 소장 개수는 보유 수량보다 크게 넣을 수 없다.
- 교환을 켠 세트에서는 칸마다 구/양 수량이 보이고, 양은 "보유 − 소장 − 예약 중" 과 같다 (소장을 따로 정하지 않은 칸은 하나).
- 교환 스위치를 끄면 그 세트로는 새 매칭이 잡히지 않는다. 이미 제안된 매칭은 그대로 진행된다.
- 세트의 모든 아이템을 1개 이상 보유하면 컴플리트 표시가 된다.
- 교환 대상에서 빼 둔 아이템은 양에 잡히지 않는다.
- 다른 사용자의 도감은 볼 수 없다.

### 도감 공유 이미지
- 도감에 추가한 세트마다 "이미지로 만들기" 를 할 수 있고, 사용자가 버튼을 눌렀을 때만 만들어진다. 자동으로 만들거나 공개하지 않는다.
- 이미지 하나는 세트 하나를 담는다: 세트 이름, 포켓 그리드(보유/미보유), 컴플리트율, 구 목록, 서비스 주소. 컴플리트한 세트는 소인이 찍힌다.
- 굿즈 사진은 들어가지 않는다. 사진이 등록된 세트도 이름표만으로 구성한다.
- 닉네임은 기본으로 들어가지 않는다. 사용자가 켰을 때만 들어간다.
- 양 목록은 기본으로 들어가지 않는다. 사용자가 켰을 때만 양의 종류가 들어가고, 수량은 들어가지 않는다.
- 만든 날짜가 들어간다.
- 보유 수량, 소장 개수, 양의 수량, 평판, 매칭·교환 내역은 들어가지 않는다.
- 만들기 전에 미리보기를 보고, 만든 이미지를 저장하거나 공유할 수 있다.
- 다른 사용자의 도감은 여전히 볼 수 없다. 공유 이미지는 본인이 만든 그림 한 장일 뿐이다.

### 매칭 제안
- 제안에 포함된 모든 참여자는 원하는 것을 1개 이상 받고, 남는 것을 1개 이상 준다.
- 한 제안에 같은 사용자가 두 번 나오지 않는다.
- 제안된 수량은 그 사용자의 양 수량을 넘지 않는다.
- 제안된 아이템은 예약 상태가 되어 다른 제안에 다시 쓰이지 않는다.
- 교환 완료 3회 미만이거나 미발송 신고가 1회 이상인 사용자에게는 3자 순환이 제안되지 않는다.
- 3자 순환 제안 화면에서 "내가 누구에게 무엇을 보내고, 누구에게서 무엇을 받는지"를 알 수 있다.

### 수락·거절·만료
- 참여자 전원이 수락해야 성사된다.
- 한 명이라도 거절하면 제안이 취소되고 예약이 모두 풀린다.
- 응답 기한(기본 24시간) 안에 전원이 응답하지 않으면 제안이 자동으로 만료되고 예약이 모두 풀린다.
- 만료 시 응답하지 않은 사람의 무응답 횟수가 1 늘고, 나머지 참여자는 다음 매칭에서 우선권을 받는다.
- 취소·만료된 뒤 풀린 아이템은 다시 매칭 대상이 된다.

### 교환 진행
- 배송 정보는 전원이 수락한 뒤에만, 그 매칭의 참여자에게만 보인다.
- 참여자는 자기가 물건을 받을 상대가 아닌, **자기가 보낼 상대**의 배송 정보만 본다.
- 발송 표시에는 배송 수단과 송장번호를 넣어야 한다.
- 발송 표시와 수령 표시를 할 수 있고, 모든 참여자가 진행 상황을 본다.
- 성사 후 발송 기한(기본 48시간)을 넘기면 보내지 않은 사람에게 경고 알림이 간다.
- 72시간을 넘기면 매칭이 분쟁 상태가 되고, 상대는 교환 취소를 선택할 수 있다.
- 응답 기한과 발송 기한은 운영자가 코드 수정 없이 바꿀 수 있다.
- 모든 수령이 확인되면 교환이 완료되고, 참여자 전원의 도감 수량이 한 번에 바뀐다. 일부만 바뀌는 경우는 없다.
- 완료 후 30일이 지나면 배송 정보가 삭제된다.

### 자동 수령과 분쟁 후 취소
- 발송 표시 후 7일(기본) 동안 수령 확인도 미수령 신고도 없으면 자동으로 수령 처리된다.
- 분쟁 상태에서 취소하면: 수령 확인된 것은 도감에 반영되고, 발송됐지만 수령 확인 전인 것은 예약이 유지되다가 수령 확인(또는 자동 수령) 때 반영되고, 미발송인 것은 예약이 풀린다.
- 자기 것은 보냈는데 받지 못한 참여자는 다음 매칭에서 우선권을 받고, 못 받은 아이템이 구 우선순위 맨 위로 올라간다.

### 알림
- 수락 요청, 발송 기한 경고, 분쟁 전환 알림은 웹 푸시와 이메일로 모두 간다.
- 그 외 알림(발송됨, 수령됨, 완료 등)은 인앱과 웹 푸시로 간다.
- 로그인 제공자에서 이메일을 받지 못한 사용자는 알림용 이메일을 직접 입력하고 인증할 수 있다. 건너뛸 수 있다.
- 첫 매칭을 수락하기 전에 "홈 화면에 추가하고 알림 켜기" 안내가 보인다.
- 푸시도 인증된 이메일도 없는 사용자는 수락 화면에서 기한 알림을 받을 방법이 없다는 경고를 본다.
- 이메일에는 배송 정보가 들어가지 않는다.

### 신고
- 성사된 매칭의 참여자만 그 매칭의 상대를 신고할 수 있다.
- 신고는 운영자가 확인해야 횟수에 반영된다. 예외: 분쟁 후 취소에서 72시간 넘게 발송 표시가 없던 사람은 자동으로 미발송 1회가 기록된다.
- 자동으로 기록된 사람은 이의를 제기할 수 있고, 운영자가 받아들이면 횟수가 되돌려진다.
- 확인된 미발송 신고가 1회면 3자 순환이 제안되지 않고, 2회면 새 매칭 대상에서 빠진다. 도감은 계속 쓸 수 있다.

### 최소 평판
- 프로필에 교환 완료 횟수, 미발송 신고 횟수, 무응답 횟수가 보인다.
- 매칭 제안 화면에서 상대의 세 가지 횟수를 볼 수 있다.
- 교환이 완료되면 참여자 전원의 완료 횟수가 1 늘어난다.

### 세트 요청
- 로그인한 사용자는 세트 추가를 요청할 수 있고, 요청의 처리 상태를 볼 수 있다.

## 9. 성공 지표 (출시 후 3개월)

| 지표 | 목표 | 측정 방법 |
|---|---|---|
| 가입자 | 500명 | 가입 계정 수 |
| 활성 세트 | 10개 | 양을 등록한 사용자가 5명 이상인 세트 수 |
| 매칭 완료율 | 50% 이상 | 교환 완료 매칭 ÷ 전원 수락한 매칭 |
| 3자 순환 완료 | 30건 | 완료된 3자 순환 매칭 수 |
| 미발송률 | 3% 이하 | 운영자가 확인한 미발송 매칭 ÷ 전원 수락한 매칭 |

보조 지표 (목표 없이 관찰): 제안 대비 수락률, 도감만 쓰는 사용자 비율, 가입 후 첫 매칭 제안까지 걸린 시간.

근거 검증 (출시 전):
- X의 교환글 표본을 모아 재게시 비율과 성사 표시 비율을 센다.
- 초기 장르 팬 5명 인터뷰: 최근 교환 시도와 실패 이유.

## 10. 전달 단계

| # | 단계 | 사용자가 얻는 것 | 상태 |
|---|---|---|---|
| 1 | 도감 단독 공개 | 로그인하고, 세트를 추가하고, 내 굿즈를 정리한다. 세트를 이미지로 만들어 공유한다 | 대기 |
| 2 | 1:1 매칭 | 구양이가 1:1 교환 상대를 찾아 준다 | 대기 |
| 3 | 교환 진행 | 배송 정보를 주고받고 완료까지 추적한다 | 대기 |
| 4 | 3자 순환 | 사람이 찾을 수 없던 교환이 성사된다 | 대기 |
| 5 | 정식 출시 | 신고·운영 도구가 갖춰진 상태로 공개한다 | 대기 |

1단계를 먼저 공개해 도감 데이터를 모은 뒤 매칭을 연다. 매칭은 데이터가 있어야 동작한다.

## 12. 결정된 사항

- 초기 시드 데이터는 프로세카. 세트·아이템 구조는 장르에 독립적으로 둔다.
- 도감 기록과 교환 참여는 분리한다. 교환 참여는 세트 단위 스위치이고 기본은 꺼짐이다. 켰을 때 기본은 종류마다 하나 소장, 구의 범위는 "빈칸 전부" 와 "고른 것만" 중에서 고른다 (최애 캐릭터만 모으는 사용자가 많다).
- 묶음 교환(2:2)은 MVP에서 제외. 나중에 확장할 수 있게 구조만 열어 둔다.
- 응답 기한 기본 24시간: 초과 시 자동 만료, 무응답 횟수 +1, 나머지 참여자 재매칭 우선권.
- 발송 기한 기본 48시간: 초과 시 경고, 72시간 초과 시 분쟁 전환과 취소 선택. 신고 누적 시 이용 제한.
- 기한 값은 설정으로 분리해 코드 수정 없이 바꾼다.
- 배송 정보는 내가 보낼 상대의 것만 본다.
- 배송 정보는 매칭마다 입력하고 매칭 단위로만 저장한다. 프로필에 기본 주소를 두지 않는다 (ADR-0004).
- 미발송 신고 횟수는 운영자가 확인한 신고만 센다. 1회면 3자 순환 불가, 2회면 매칭 정지(도감은 계속 사용, 해제는 운영자).
- 가입은 만 14세 이상만. 가입할 때 확인받는다.
- 교환 수단은 송장번호가 나오는 것만 안내하고, 발송 표시에 배송 수단과 송장번호가 필수다. 배송비는 각자 부담.
- 굿즈 이미지는 운영자가 촬영한 실물 사진. 없으면 이름과 기본 실루엣. 권리자 요청 시 내린다.
- 활성 세트 = 양을 등록한 사용자가 5명 이상인 세트.
- 알림은 인앱 + 웹 푸시 + 이메일(Resend). iOS 는 홈 화면에 추가한 PWA 에서만 푸시가 오므로 이메일이 대체 수단이다.
- 수락할 때 배송 정보를 함께 입력한다. 성사 전에는 본인에게만 보이고, 거절·만료되면 즉시 지운다.
- 발송 후 7일(설정값) 동안 수령 확인도 미수령 신고도 없으면 자동 수령 처리한다.
- 분쟁 후 취소는 leg 를 수령 확인 / 발송 후 미확인 / 미발송 세 가지로 나눠 처리한다.

- 분쟁 후 취소의 미발송자는 자동으로 미발송 1회. 이의 제기와 운영자 정정이 가능하다.
- 거절·만료된 같은 조합(보내는 사람, 받는 사람, 아이템)은 7일(설정값) 동안 다시 제안하지 않는다.
- 저장소는 공개로 둔다.
- "도감 공개 프로필" 과 "도감 공유 이미지" 를 나눈다. 공개 프로필은 MVP 제외, 공유 이미지는 MVP 포함이고 도감 단독 공개 때 함께 연다 (도감이 퍼질 수단). 공유 이미지에는 굿즈 사진을 넣지 않고(저작권), 닉네임과 양 목록은 기본으로 넣지 않는다. 양 목록을 켜도 종류만 넣고 수량은 넣지 않는다.
- 도감 칸의 비율은 세트마다 정한다 (`1:1` 또는 `3:4`, 기본 `1:1`). 굿즈마다 모양이 다르기 때문이다.
