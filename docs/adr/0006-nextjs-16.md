# ADR-0006: Next.js 16 과 Node 26 으로 시작

**Date**: 2026-11-15
**Status**: accepted
**Deciders**: 프로젝트 오너, Claude

## Context

기반 문서는 웹 스택을 "Next.js 15" 로 적었다. Sprint 1 에서 앱을 만들기 직전에 확인해 보니 최신 안정 버전은 16.4.6 이었다 (16.0.0 은 2025-10-22 출시). 15 는 15.5.29(2026-11-03)까지 패치가 나오는 이전 메이저다. 아직 앱 코드가 한 줄도 없어서 지금은 어느 쪽을 골라도 옮길 것이 없다.

Node 는 Vercel 이 지원하는 최신 LTS 로 고정하기로 했다. Vercel 문서 기준 지원 버전은 26.x(기본) · 24.x · 22.x 다.

## Decision

`apps/web` 은 Next.js 16 (App Router, Turbopack) 으로 시작한다. Node 는 26.x 로 고정한다 (`.nvmrc`, 루트 `package.json` 의 `engines.node`).

Next.js 관련 구현을 하기 전에 `apps/web/node_modules/next/dist/docs` 의 해당 문서를 먼저 읽는다. 기억이나 스킬의 안내가 그 문서와 다르면 문서를 따른다 (CLAUDE.md 규칙).

## Alternatives Considered

| | Next.js 15.5 | Next.js 16.4 (선택) |
|---|---|---|
| 상태 | 이전 메이저, 패치 중 | 현재 안정 버전, 출시 후 1년 |
| 기반 문서와의 일치 | 그대로 | 스택 표기를 고쳐야 한다 (이 ADR 과 함께 고쳤다) |
| 이후 부담 | 출시 전후에 16 으로 올리는 작업이 생긴다 | 없음 |
| 함께 오는 버전 | React 19.1, Tailwind 4 | React 19.3, Tailwind 4.3 |
| Node 26 빌드 | 성공 (확인함) | 성공 (확인함) |
| `pageExtensions` | 있음 | 있음, 동작 확인함 |
| 위험 | 낮음 | 규칙이 바뀐 곳이 있어 익숙한 방식이 틀릴 수 있다 |

### 대안 1: Next.js 15 로 시작
- **Pros**: 문서 변경이 없다. 자료와 예제가 가장 많다.
- **Cons**: 새 프로젝트를 이전 메이저로 시작한다. 코드가 쌓인 뒤에 16 으로 올려야 한다.
- **Why not**: 옮길 코드가 없는 지금이 가장 싸다.

### 대안 2: Node 24 로 고정
- **Pros**: 26 보다 오래 쓰여 검증이 많다.
- **Cons**: Vercel 의 기본값이 아니다.
- **Why not**: 26 에서 문제가 없었다. 문제가 생기면 24 로 내린다 (아래 "되돌리는 기준").

## 확인한 사실 (2026-11-15, Node 26.13.1)

- `create-next-app@15` (15.5.29) 와 `create-next-app@16` (16.4.6) 으로 만든 앱이 **둘 다 Node 26 에서 빌드된다**.
- Next.js 16.4.6 + React 19.3.0 + Tailwind 4.3.3 에서 `shadcn init` (shadcn 4.23, `base-nova` 프리셋, Base UI) 이 오류 없이 끝나고, 그 뒤 `pnpm dev / build / lint / typecheck / test` 가 모두 통과한다.
- `@supabase/ssr` 0.12.7 의 peer 의존성은 `@supabase/supabase-js` 뿐이고 Next.js 버전을 제한하지 않는다. 설치와 실제 연동은 Sprint 2 에서 한다.
- **`pageExtensions` 로 테스트 로그인 경로를 빌드에서 빼는 방식이 16 에서 동작한다** (testing.md E6, E7 의 전제). 임시 앱에 `app/e2e-login/route.e2e.ts` 를 두고 시험했다.

  | 빌드 | 라우트 목록 | 산출물에 표식 문자열 | `GET /e2e-login` |
  |---|---|---|---|
  | 운영 빌드 (`e2e.ts` 확장자 없음) | 없음 | 0개 파일 | 404 (실행할 때 `E2E_BUILD=1` 을 켜도 404) |
  | E2E 빌드 (`E2E_BUILD=1`) | `ƒ /e2e-login` | 2개 파일 | 200 |

  확장자 목록은 빌드할 때 정해지고 실행할 때의 환경 변수로는 바뀌지 않는다. 대안은 필요 없다.

## Consequences

### Positive
- 출시 전에 메이저 버전을 올리는 작업이 없다.
- 개발과 빌드 모두 Turbopack 이 기본이다.
- 버전에 맞는 문서가 패키지 안에 들어 있어 (`node_modules/next/dist/docs`) 구현할 때 그 버전의 규칙을 바로 확인할 수 있다.

### Negative
- 15 기준으로 쓰인 글, 예제, 스킬 안내가 맞지 않을 수 있다. 구현할 때마다 번들 문서를 확인하는 비용이 든다.
- 기반 문서의 "Next.js 15" 표기를 고쳤다 (CLAUDE.md, PRODUCT.md, TASKS.md).

### Risks
- **익숙한 방식이 16 에서 틀릴 수 있다** → 구현 전에 번들 문서의 해당 항목을 읽는다. 스킬(`ecc:nextjs-turbopack` 등)의 안내와 문서가 다르면 문서를 따르고 차이를 알린다.
- **미들웨어 파일 이름이 `proxy.ts` 다** (15 까지는 `middleware.ts`). Supabase 세션 갱신 예제가 `middleware.ts` 로 되어 있으면 `proxy.ts` 로 옮겨 쓴다 (Sprint 2).
- **`create-next-app` 기본 설정에 `cacheComponents: true` 가 켜져 있다.** 데이터를 읽는 방식과 캐시 규칙에 영향을 준다. 데이터를 처음 읽는 Sprint 2~3 에서 번들 문서(`cacheComponents.md`, `08-caching.md`)를 읽고 유지할지 정한다. 로그인한 사용자별 화면(도감)이 잘못 캐시되지 않는지 E2E 로 확인한다. → TASKS 2.9 에서 결정하고 별도 ADR 로 남긴다. 보장 항목은 testing.md E8.
- **타입 검사에 라우트 타입 생성이 필요하다** → `typecheck` 스크립트는 `next typegen && tsc --noEmit` 이다.
- **Node 26 이 의존성과 맞지 않을 수 있다** → 지금은 문제가 없다. 생기면 아래 기준으로 내린다.

### 되돌리는 기준
- Node: 필요한 의존성이 26 에서 동작하지 않으면 24.x 로 내리고 이 ADR 에 이유를 적는다.
- Next.js: 15 로 내리지 않는다. 16 에서 막히는 기능이 있으면 그 기능의 대안을 찾는다.
